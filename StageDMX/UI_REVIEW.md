# App UI 评审与改进方案

> 评审依据：`res/layout/*.xml` 全量 + 真机截图（推子/效果/灯具/文件/设置页）。
> 本轮已完成 **A（信息架构）**；B~E 待接真机后逐页验证再改。

---

## 一、评审结论：结构性问题比视觉问题更严重

### 1. 同一件事有两三个入口（真实重复）

| 功能 | 入口 1 | 入口 2 | 问题 |
|---|---|---|---|
| 本地灯库列表 | 灯具页 | 文件页 → "App灯库" | **同一份数据（`fixtureStore.fixtures`）列两遍**，一个用来"应用/加实例"，一个用来"上传" |
| 记录一步 | 推子页"记录" | 程序页"记录一步" | 同一个 `steps.addStep`，两处入口 |
| 选择要控制的灯 | 顶部实例芯片多选 | 实例管理页勾选 | 同一个 `selectedInstanceIds` |
| 设置通道数 | 顶部 16/32/64 预设 | 顶部输入框 | 同一个 `setChannelCount` |

重复入口会让用户不确定"该去哪"，也让代码里同一份状态有两个刷新路径。

### 2. 顶部栏塞了三类不相关的东西

```
[设备●] [实例芯片组…] [实例管理] [16][32][64] [512]
  连接      选择灯具        跳页      通道数    通道数
```
实例多的时候中间只剩很窄一条；而"通道数"在**有实例时本来就不用**（被隐藏），布局却在为它留位。

### 3. 底部导航 6 项已超 Material 上限

Material 的 `BottomNavigationView` 上限是 5；为了放第 6 个"文件"，还专门写了一个
`SixItemBottomNavigationView` 去覆写 `getMaxItemCount()`。而 6 项里"文件"和"设置"都是低频，
真正高频的"实例管理"反而不在导航里。

### 4. 推子页信息密度失控

30+ 条通道**平铺**在一个列表里，找"图案盘"要滑很久；没有分组、没有搜索。
而且**看不出哪条通道正被效果驱动** —— 此时滑条显示的值是效果写进去的，用户拖它会"弹回去"，
但界面没有任何提示。

### 5. 效果页纵向空间被两件事抢

12 行效果列表（`layout_weight=1`）和 7 组参数控件（wrap_content）在同一个竖排里抢高度：
参数区一展开，列表几乎看不见；列表看全时，参数又会被挤到屏幕外。

### 6. 缺"当前状态总览"

现场最需要一眼看到的：主控多少、有几个效果在跑、程序在不在放、**DMX 输出是否正常**。
目前全都没有。固件其实已经有 `dmx_tx_ok()/dmx_tx_fails()`，只是没接进协议。

## 二、改进方案

### A. 信息架构（✅ 本轮已实施）

```
底部导航 5 项： 推子 | 程序 | 效果 | 灯具 | 设置
```

- **文件管理并入"灯具"页**：顶部页签 `App灯库 / 设备灯库 / 文件管理`
  → 消除"App 灯库列两遍"，且腾出导航位
  → 格式筛选（XML/D4/R20）收进 App灯库 里的小行
  → U盘模式开关放进"设备/文件"容器（只有访问设备存储才用得到）
- **实例管理 / 灯库编辑**：不在导航里，由设置页与顶栏进入
- 删除 `SixItemBottomNavigationView`（回到标准控件）
- **页面索引集中成 `Page` 常量**：原来散落着 `pager.currentItem = 5/6/7` 这类魔数，
  一增删页面就会错位（本次改动就差点踩到）
- 灯具页第三个按钮文案修正：`编辑` → **`批量`**（它实际是批量选择）

### B. 推子页：按功能分组折叠（待做，收益最大）

```
主控亮度 ▬▬▬▬▬▬▬▬ 100%
[全黑] [定位] [Flash]

▼ 调光 (2)                    ← 分组标题，点收起；右侧标出"被效果占用 N"
    1.调光      ▬▬▬▬  0
    2.调光微调  ▬▬▬▬  0
▼ 颜色 (5)
    4.色盘      ▬▬▬▬  0
▶ 位置 (4)                    ← 收起
▶ 图案 (3)
▶ 光束/控制 (6)
```
- 分组依据：灯库 attribute 前缀（dim / color* / gobo* / focus|zoom|iris|frost / pan|tilt / 其它）
- **被效果占用的通道**：名称前一个小圆点 + 滑条变暗，拖动时提示"该通道正被效果驱动"
  （数据现成：`FxEngine.occupiedChannels`，但它是 private，需要暴露一个查询接口）
- 裸通道模式（无灯库）保持平铺不分组

### C. 效果页：运行中卡片 + 列表改网格（待做）

```
[运行中] 圆形摇动 ✕   频闪 ✕
波形[正弦▾] 方向[正序▾] 包络[无▾]
幅度 ▬▬▬ 128      速度 ▬▬▬ 146
扩散 ▬▬▬ 0°       相位 ▬▬▬ 0°
[圆形][水平][垂直][频闪][RGB][放大]
[调焦][色盘][图案][自转][摇动][切割]     ← 3 列网格，省一半高度
[效果预设 ▾]                              ← 常驻行收成一个按钮，点开弹窗管理
```

### D. 设置页分组 + 实例管理入口（待做）

```
外观        语言 / 推子页排列方式
多灯同步    跟随延时 / 延时
灯库与实例  灯库编辑 / 实例管理 / 重新导入灯库
高级        DMX 输出状态 / 清空数据
```

### E. 状态总览（待做，需要固件配合）

推子页顶部一行：
```
主控 100% · 运行 2 个效果 + 程序1 · U1 ✓  U2 ✓
```
- 效果与程序：App 侧已有（`FxEngine.activeFxIds` / `playingSlots`）
- **U1/U2 输出状态**：需要把 `dmx_tx_ok()/dmx_tx_fails()` 加进状态同步帧
  （`0x82` 头里有 flags 空闲位），固件侧约 10 行
